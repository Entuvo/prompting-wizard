# Day 28 — Prompt library: save the slots, not just the words

## Concept

Rewriting a prompt from scratch each time re-solves problems already solved last week — the phrasing that stopped the hedging, the constraint that stopped the padding — reinvented because nothing was kept.

Saving the words is not the same as saving the prompt. A saved prompt stays low on the shelf until two more things are marked: which parts change between uses, and how it has failed before. "{{TASK}}: summarise in five bullets, one per risk. Known failure: invents a risk when fewer than five exist — check the count first." The slot says what to substitute; the failure note says what to watch for, so the same bug doesn't resurface later.

Marking the slot without the failure gets you partway: a template a stranger could reuse, but one still liable to fail the same silent way. The failure note turns reusable into reliable — specific enough that reading it once prevents a repeat.

Here is the test: open one saved prompt. Could a stranger use it correctly, and would they know, before running it, the one way it's failed before?

## Before / After

**Before**

> Summarise {{TASK}} in five bullets, one per risk.

**After**

> **Saved prompt: risk-summary**
> Template: `Summarise {{TASK}} in five bullets, one per risk.`
> Slot: `{{TASK}}` — the document or diff being reviewed.
> Known failure: invents a fifth risk when fewer than five exist. Fix: state the count found before listing, and stop there if it's under five.

The prompt itself barely changed. What's new is the record around it — the slot named, the failure that's already happened, and the fix, so the next use starts from where the last one ended instead of from zero.

## Exercise

Pick one of your recurring tasks. Write a single prompt for it.

### Novice

Take a prompt you've written more than once for {{TASK}}. Save it with every variable part marked as a named slot — the slots only, nothing yet about how it has failed — and send the saved prompt.

### Working

Save a prompt for {{TASK}} with every variable part marked as a named slot, and note underneath each way you remember it failing.

### Advanced

Save a prompt for {{TASK}} with every slot named and every failure mode written specifically enough that a stranger would recognise the failure before running it — name what the bad output looked like, not just the category.
