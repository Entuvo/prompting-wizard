# Day 28 — Prompt library: save the slots, not just the words

## Concept

Rewriting a prompt from scratch each time means re-solving problems already solved last week — the phrasing that stopped the hedging, the constraint that stopped the padding — reinvented because nothing was kept.

Saving the words is not the same as saving the prompt. A saved prompt stays low on the shelf until two more things are marked: which parts change between uses, and how it has failed before. "{{TASK}}: summarise in five bullets, one per risk. Known failure: invents a risk when fewer than five exist — check the count first." The slot says what to substitute; the failure note says what to watch for, so you don't rediscover the same bug on the tenth use.

Marking the slot without the failure gets you partway: a template a stranger could reuse, but one that can still fail silently the same way it failed you. The failure note is what turns reusable into reliable — specific enough that reading it once prevents the mistake happening a second time.

Here is the test: open one saved prompt. Could a stranger use it correctly, and would they know, before running it, the one way it's failed before?

## Before / After

**Before**

> Summarise {{TASK}} in five bullets, one per risk.

**After**

> **Saved prompt: risk-summary**
> Template: `Summarise {{TASK}} in five bullets, one per risk.`
> Slot: `{{TASK}}` — the document or diff being reviewed.
> Known failure: invents a fifth risk when fewer than five exist. Fix: state the count found before listing, and stop there if it's under five.

The prompt itself barely changed. What's new is the record around it — the slot named, the failure that's already happened, and the fix, so the next use starts from where the last one ended instead of from zero.

## Exercise
