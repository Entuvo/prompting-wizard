# Day 29 — Capstone I: build it

## Concept

The capstone rubric is a ladder, not a pass/fail line. Bottom rung: the prompt works once, on the case you tried. Next: it survives a couple of close variants. The rung above needs two things together — the prompt is specified, and it holds up across cases that genuinely differ from each other.

That's the rung today targets, and no higher. There's no written criteria and no documented failure modes yet — that's tomorrow's work. Pick the task you'd be most annoyed to keep hand-holding through a model, one you run often enough that a weak prompt costs real time, and build the prompt you'd actually save: every lever and technique from the last four weeks, engaged where the task needs it.

Reaching that rung honestly caps you around anchor 3, maybe a strong 4 if evaluation sneaks in early. Anchor 5 needs day 30's work — eval criteria and documented failures — not more polish today.

Here is the test: run your prompt against two cases as different from each other as your recurring task allows. If either breaks, it isn't specified yet — it's still an example.

## Before / After

**Before**

The tutor asks the learner which of their recurring tasks costs them the most when the prompt is weak — not the easiest task, the one where a bad prompt actually hurts. The learner names it in their own words, unprompted by any example from the tutor.

**After**

The learner writes the production prompt for that task: every lever deliberately set, and every technique from this week applied where the task needs it. The tutor runs it against two cases that genuinely differ from each other and scores it against `rubrics.md#capstone`, and the learner revises until it holds up on both — anchor 3, honestly reached, is the target for today.

## Exercise

Ask the learner to name their highest-value recurring task per `## Before / After`, then record it, in the learner's own words, in the day-29 `## Log` line, so day 30 can read it back without asking again.

### Novice

Ask the learner to write a first pass at the production prompt for their named task, run it once, and confirm it produces the deliverable they wanted — anchor 1, the floor everyone starts from.

### Working

Ask the learner to run their prompt on two cases of the named task that differ from each other, not just from the original, revising it — without rewriting it per case — until it holds up on both.

### Advanced

Ask the learner to specify the prompt fully — every lever and technique the task actually depends on — then run it on the most different case they can construct from their real work. If it holds, they've reached anchor 3 honestly. Tell them anchor 4–5 is day 30's job, not something to chase today by adding untested claims.

## Rubric

Score against `rubrics.md#capstone`.
