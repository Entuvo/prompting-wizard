# Day 26 — Token economy: cut what doesn't earn its place

## Concept

Context you added because it might matter costs the same as context that does matter — the model reads both, weighs both, and a fact stated once is easier to find than the same fact buried in three paragraphs of padding around it. Unused material doesn't just waste tokens; it dilutes the signal the model needs.

Cutting is not the same as guessing. Delete a section, rerun, and compare: if the output holds steady, that section wasn't earning its place. If it degrades, you've learned something you didn't know before you cut — that section mattered, and now you can say which one, instead of assuming.

The test is the cut, not the eyeballing. A paragraph that reads as necessary can turn out to be inert once removed; a paragraph that reads as boilerplate can turn out to be load-bearing. Neither is obvious from staring at the prompt before you run it.

Here is the test: cut a third of your context, rerun, and compare outputs side by side. Whatever changed tells you what the missing third was doing.

## Before / After

**Before**

> This has come up before in a few different forms, and the discussion last time about whether to change the process is still unresolved — worth knowing, since some of the same names and numbers resurface here. Also, unrelated: the team switched project trackers last quarter, which caused some confusion for a few weeks. Produce {{TASK}}, and keep it under 300 words.

**After**

> This has come up before in a few different forms, and the discussion last time about whether to change the process is still unresolved — worth knowing, since some of the same names and numbers resurface here. Produce {{TASK}}, and keep it under 300 words.

The tracker aside — about a third of the context — never fed the task, and cutting it changed nothing when tested. The paragraph about the unresolved discussion stayed because a rerun without it changed what counted as resolved. Keeping it wasn't a guess; it was confirmed.
