# Day 3 — Adjective: quality constraints

## Concept

"Write a summary of {{TASK}}" names an artifact and an operation. It still says nothing about what makes the summary good enough to keep. The model will write something summary-shaped and stop, because nothing told it what would make you reject that output.

Adjectives are quality constraints. "Blunt", "jargon-free", "actionable" each rule something out: hedging, insider vocabulary, advice nobody can act on. A quality word that rules nothing out — "good", "high-quality", "professional" — is not a constraint, it is decoration. Any output can claim to be professional.

Two qualities usually do the real work: the one you'd complain about first if it were missing, and the one you'd complain about second. Name both. A third rarely earns its place, and padding the list with qualities that don't matter here just adds noise the model has to reconcile.

Test it this way: for each adjective in your prompt, ask what output it would make you reject. If you can't answer, cut the word.

## Before / After

**Before**

> Write a summary of {{TASK}}.

**After**

> Write a blunt, jargon-free summary of {{TASK}} that a new joiner could act on.

"Blunt" rules out hedged, diplomatic phrasing. "Jargon-free" rules out insider shorthand. "That a new joiner could act on" is the test a reader could apply to check both landed.

## Exercise

Pick one of your recurring tasks. Write a single prompt for it.

### Novice

Fill the blanks with two qualities that would make you reject the output if either were missing, then send the completed line as your prompt.

> Write a ________, ________ summary of {{TASK}}.

### Working

Write a prompt for {{TASK}} that names the two qualities that matter most, worded specifically enough that a generic output would visibly fail one of them.

### Advanced

Write a prompt for {{TASK}} that names exactly three qualities. For each one, be ready to say in one sentence what it rules out. If a quality doesn't rule anything out, replace it.
