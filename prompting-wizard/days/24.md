# Day 24 — Self-critique loops: name a check that can fail

## Concept

"Review your answer before you finish" asks for a check with no test attached. The model rereads its own output looking generally satisfied — nothing tells it what failing would look like, so nothing ever fails.

A working check names a property the output could plausibly lack, one you could point to on a bad day: "every number cited here should trace to a figure in {{TASK}}; check each one and list any that don't." That check has a failure mode — a number with no source — so the model can go looking for it specifically, instead of nodding at the whole.

The loop isn't finished until it says what to do when the check fails. "If you find one, replace it or flag it as unverified" turns a check into a correction; without that line the model finds the problem and reports it anyway, unfixed.

Here is the test: describe, in one sentence, what your output would look like if it failed your check. If you can't, the check can't fail either, and it isn't checking anything.

## Before / After

**Before**

> Write {{TASK}}.

**After**

> Write {{TASK}}. Before finishing, check every factual claim against the source material; if any claim doesn't trace to something in the source, cut it or mark it "unverified."

The task is unchanged. What's new is a check with a name — traceability to source — and an action for when it fails, so a single pass becomes a pass plus a verification the model can actually fail.

## Exercise

Pick one of your recurring tasks. Write a single prompt for it.

### Novice

Write a single-pass prompt for {{TASK}}, then add one named check the model applies to its own output before finishing — the check only, with nothing said about what to do if it fails — then send the completed prompt.

### Working

Write a prompt for {{TASK}} with a check specific enough that you can say, in one sentence, what a failure would look like, plus an instruction to do something about it when it fails — "fix it" or "try again", without naming what to do to the failing element.

### Advanced

Write a prompt for {{TASK}} whose self-check the model could plausibly fail — not one it will always pass by default — and whose action on failure names what to do to the failing element: the operation to perform on it, not "fix it". Say in the prompt what output would trigger that correction.
