# Day 23 — Agent and tool prompting: tools, timing, and done

## Concept

An assistant may have tools for reading documents, searching sources, or working with a spreadsheet. "Use the tools to sort out {{TASK}}" says neither which tool serves which purpose nor when the work should stop.

A prompt becomes useful when it connects each available tool to a situation. For a training plan, document search can locate requirements; spreadsheet tools can compare the supplied options against those requirements. Naming a tool does not make it available: check what the assistant can actually access.

The stopping condition matters just as much. "Stop after filling the table" can be satisfied with guesses. "Every option is checked against every requirement, with a source for each answer and missing information marked unknown" describes an outcome you can inspect. Unknowns are a legitimate result, not a reason to keep searching forever or invent an answer.

State any limits on actions too: preparing a comparison does not require contacting providers or making bookings. Putting the stopping condition first is a useful habit, not a scoring requirement.

Here is the test: could the assistant satisfy your definition of done by going through the motions? Replace that shortcut with evidence you can check.

## Before / After

This fixed example illustrates the technique; apply it to your own task in the exercise.

**Before**

> Use the tools to prepare a comparison of workshop venues from the supplied requirements and approved options. Do not contact anyone or make bookings.

**After**

> Prepare a comparison of workshop venues from the supplied requirements and approved options. Use document search to locate the requirements, then spreadsheet tools to compare each option against every requirement. Use only the supplied material. Stop when every option has an answer for every requirement, with a document and page or section supporting each answer. Use "unknown" only after checking the supplied material; list the specific sections checked for that requirement and explain what information they lack, so the reader can verify each unknown against those sections. Return the comparison and any unresolved questions. If a required tool or source is unavailable, report that limit instead of claiming the comparison is complete. Do not contact anyone or make bookings.

The tools have specific jobs and a reason to be used. "Done" means coverage and traceable answers, not merely a filled table. Missing evidence stays visible. The learner can inspect the comparison against the supplied material without knowing how the tools are implemented.

## Exercise

Pick one of your recurring tasks involving tools, such as comparing workshop venues, checking stock against a request list, or gathering sources for a research brief. Ask the tutor which tools are available for the practice run, then name those tools in your prompt. If the required tools or sources are missing, you can practise the wording, but execution remains unavailable.

The tutor checks the actual isolated-run tools and source access before the learner writes, explains them in plain language, and ensures both comparison runs can access identical supplied material. Do not infer access from a tool name in the prompt. Follow the Day 23 unavailable-execution exception in SKILL.md if access cannot be confirmed. After a run, check the returned work against the learner's done-condition and cited source locations before calling it complete; report any unverified claims.

### Novice

Write a prompt for {{TASK}} that names which tools to use and their rough sequence, but gives only the vague stop condition "stop when it is done." Leave that condition vague in the prompt you send.

### Working

Write a prompt for {{TASK}} that states which tools to use, when each applies, and a specific done-condition that motion alone can satisfy, such as stopping after filling a table. State how that condition could be gamed, but do not close the hole in the prompt you send.

### Advanced

Write a prompt for {{TASK}} whose stop condition requires a checkable outcome. State one way an assistant could appear finished without doing the real work, then rewrite the condition so that shortcut no longer counts as done. Include how it should report unavailable tools or missing evidence.
