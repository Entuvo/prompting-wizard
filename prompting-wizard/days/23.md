# Day 23 — Agent and tool prompting: the stop condition first

## Concept

"Use the tools to sort out {{TASK}}" hands an agent freedom with no exit. Without a stop condition, it keeps calling tools past the point of usefulness, or declares victory after the first one that returns something plausible — both look identical from outside: a transcript full of calls with no way to tell whether the task actually finished.

Define done before naming a single tool. "Stop when the tests pass and the diff is under 50 lines" is a condition you can check against the transcript afterwards. Only once that's fixed does tool choice make sense — you can name which tool serves each step, because you already know what the last step has to prove.

Order matters, not just presence. A condition placed after a list of tools reads as an afterthought; agents tend to satisfy whatever came first, and naming tools before the condition invites picking ones that feel thorough rather than ones it needs.

Here is the test: cover the tool list in your prompt. Can you still state, from what's left, exactly when the agent should stop?

## Before / After

**Before**

> Use the tools to sort out {{TASK}}.

**After**

> Stop when {{TASK}} passes its existing checks and you can point to the specific change that fixed it. Until then, use the search tool to find the failing area, the edit tool to change it, and the test tool to verify — in that order, one change at a time.

The stop condition now comes first and names a state you can check against the transcript. The tools follow it, each tied to a step the condition requires, instead of a list offered up front with no claim on when they're done.
