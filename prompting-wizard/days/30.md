# Day 30 — Capstone II: harden it

## Concept

A prompt that works on the example it was built against has proven one thing: that it works on that example. A single success doesn't say whether it generalises, or force you to define "working" — not until you check it against a case you didn't design for.

Hardening has three parts: written criteria — day 25's discipline — say what a pass looks like before you run anything; an unfamiliar case tests whether the prompt generalises or just memorised its example; and when that case breaks something, the failure mode gets written down, specific enough not to relearn in three months.

The rubric's rungs are exact, not impressionistic. Day 29's target — "specified and works on varied cases" — sits at anchor 3 only because it has "no written evaluation criteria" yet. Add the criteria and evaluate against them: anchor 4, "evaluated against written criteria, with failure modes noted but not systematically." Document what the unseen case breaks, systematically: anchor 5, the same evaluation with failure modes "documented" rather than just noted.

Here is the test: run your day-29 prompt on a case you didn't build it for. What breaks first?

## Before / After

**Before**

The tutor reads the day-29 `## Log` line and takes the task recorded there, along with the prompt the learner finished day 29 with — not a fresh question to the learner.

**After**

The learner writes criteria for that prompt if day 25's criteria weren't reused, runs the prompt on a case unlike the one it was built against, and documents what broke. The tutor helps fix only what the unseen case actually revealed, then the prompt is re-run against the same criteria to confirm the fix held.

## Exercise

Read the task and prompt recorded in the day-29 `## Log` line before presenting a tier; do not ask the learner to restate it.

### Novice

Ask the learner to write three checks for the day-29 prompt, then run it once more on the same case and score it against those checks.

### Working

Ask the learner to run the day-29 prompt on a case unlike the one it was designed for, name what broke, and write the failure mode down specifically enough that someone else could recognise it.

### Advanced

Ask the learner to run the day-29 prompt against an unseen case, fix only what that case revealed, and rerun until it passes the written criteria on both the original case and the unseen one.

When the revised prompt passes both, set `current_day` to 31 in `PROGRESS.md`. Read the eleven baseline scores from the Day 0 `## Log` line — the only surviving record of the learner's starting point, since `## Levers` is overwritten as the course progresses — and show them alongside the current `## Levers` scores, lever by lever. Then tell the learner the course is complete: `SKILL.md` will not present another day once `current_day` is above 30.
