# Day 30 — Capstone II: harden it

## Concept

A prompt that works on the example it was built against has proven exactly one thing: that it works on that example. Nothing in a single success tells you whether it generalises, and nothing forces you to write down what "working" even means until you check it against a case you didn't design for.

Hardening has three parts, and skipping one caps the score. Written criteria — day 25's discipline — say what a pass looks like before you run anything. A case unlike the one you built against tests whether the prompt generalises or just memorised its example. When that case breaks something, the failure mode gets written down, specific enough you don't relearn it in three months.

A prompt that merely works once sits at a 1 or 2. Add criteria and it clears 3. Run it on the unseen case, document what broke, and fix it — that's what separates 4 from 5.

Here is the test: run your day-29 prompt on a case you didn't build it for. What breaks first?

## Before / After

**Before**

The tutor reads the day-29 `## Log` line and takes the task recorded there, along with the prompt the learner finished day 29 with — not a fresh question to the learner.

**After**

The learner writes criteria for that prompt if day 25's criteria weren't reused, runs the prompt on a case unlike the one it was built against, and documents what broke. The tutor helps fix only what the unseen case actually revealed, then the prompt is re-run against the same criteria to confirm the fix held.

## Exercise

Read the task and prompt recorded in the day-29 `## Log` line before presenting a tier; do not ask the learner to restate it.

### Novice

Ask the learner to write three checks for the day-29 prompt, then run it once more on the same case and score it against those checks.

### Working

Ask the learner to run the day-29 prompt on a case unlike the one it was designed for, name what broke, and write the failure mode down specifically enough that someone else could recognise it.

### Advanced

Ask the learner to run the day-29 prompt against an unseen case, fix only what that case revealed, and rerun until it passes the written criteria on both the original case and the unseen one.

When the revised prompt passes both, set `current_day` to 31 in `PROGRESS.md` and show the learner their `## Levers` scores from the Day 0 assessment alongside their current `## Levers` scores, lever by lever. Then tell them the course is complete — `SKILL.md` will not present another day once `current_day` is above 30.
