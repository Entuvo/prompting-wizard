# Large programs and parallel coverage

Use for many dependent units, authorized parallel coverage or work that needs durable supervision. A small task stays with ordinary [delivery](delivery.md); do not create a store, hierarchy or pilot ceremony for a routine edit. Adapt pstack's orchestration, swarm and decision-trail disciplines through [native host controls](codex.md). GPT-6 Astra leads engineering; exact Claude Opus 5.5 supplies independent review when available. A file naming a role cannot register that model or an agent.

## Frame and pilot

Define a countable done predicate, scope exclusions, known dependencies, budget/time constraints and concrete accepted evidence. Resolve engineering and private-record roots using [resume](resume.md). Reuse the current plan/checkpoint; introduce the existing pstack store only when multiple units need it. Records may live outside source. They do not grant authority or automatically supervise workers.

Plan each unit with `ID / outcome / acceptance / dependencies / owner + writable boundary / current source identity / expected evidence / state`. Assign a single owner to coupled writes and stack topology. Dispatch only dependency-ready units with actual upstream results, interfaces, constraints and documentation evidence included or accessible. Ordering alone does not relay context. A worker without necessary inputs remains blocked; do not make it reconstruct private chat context.

Before scaling a novel or repeated workflow, pilot one representative unit through brief, execution, checks, independent review and the authorized delivery boundary. Landing belongs in the pilot only when authorized. Choose a unit that exercises likely integration/failure paths. Fix the brief, verification recipe or unit size from observed pilot results before scaling. For near-identical cheap units, the first normal unit is enough; avoid a separate expensive rehearsal. A failed pilot leaves the corresponding scale-up gate open.

## Dispatch, drain and recover

Use actual host capacity and budget to bound in-flight work. No fixed ten-lane team, cloud default, nested hierarchy or role wizard. Prefer a small rolling window; add a coordinator only when observed coordination load warrants it. Each brief names outcome, absolute cwd, owned/prohibited paths, upstream context, acceptance, checks, return shape and limits. Share standing orders with every new worker and resume. Sample a brief and its real output during each substantial wave; a broken shared brief halts affected refills until corrected.

Track every requested slot separately from successful dispatch. For each dispatched worker keep `worker ID / unit or slice / source identity / expected return / last observed host state / result or dropout / evidence / ownership resolution`. Record rejected dispatches as undispatched gaps. Agent labels, elapsed time and transcript modification time are not liveness or completion evidence.

At a completion notification, retain its pointer. At bounded drain points—after a critical edit/merge decision, wave completion, relevant wake and before reporting—snapshot pending pointers and classify each as needing inspection, accepted, failed, blocked, dropout or superseded. Keep the drain bounded; later arrivals enter the next drain. Inspect files, receipts and relevant diffs before accepting results. Do detailed verification as explicit work outside queue bookkeeping. Recompute dependency-ready work only after prerequisite results are accepted. The inbox CLI records/drains pointers; it does not perform any of these judgments.

Never silently redo a missing worker's slice. Record the failed scope and cause, then explicitly rerun, absorb or leave a coverage gap. Reject returns missing required source identity or measurement method; request one corrected return/rerun, then retain an explicit gap if still absent. Bound other retries by observed cause and agreed budget: one retry for a transient problem, then change approach or report the blocker. Persistent broken infrastructure or a shared faulty premise stops affected new work while independent work continues.

On interruption, cancellation or reassignment, inspect native worker status, interrupt when appropriate and wait for acknowledgement before releasing its writable boundary. A timeout or requested interrupt does not prove writes stopped. Preserve and inspect partial files; invalidate affected checks/reviews. If acknowledgement cannot be established, keep ownership blocked or use an isolated new output with no conflicting writes. Reconcile a late result against current files, dependencies and accepted evidence before salvaging it; never blindly overlay or merge it.

## Coverage and races

For coverage, enumerate required slices before dispatch. Aggregate `required / returned / evidence-qualified / failed / blocked / dropout / superseded` without conflating them. Every required slice needs valid evidence before claiming complete coverage. N−1 returns can support a partial report, never a full pass. Show overlapping slices and uncovered boundaries explicitly; do not multiply confidence by worker count.

For an authorized race, declare `first passing result`, `rank all`, or `best of N` before dispatch, together with acceptance criteria and tie handling. Each arm gets comparable inputs, exact revisions and, for measurements, a common method, sample definition/count and order. Apply the declared rule to qualified results only. A first-pass race need not wait for all implementations, but must interrupt/drain and account for remaining workers before reusing their files; best-of/rank-all remains partial if required arms disappear. General races remain optional; [architecture](architecture.md) owns its required structural alternatives and [evaluations](evaluations.md) owns blinded workflow comparisons.

## Decision trail and independent audit

For a long program, keep one append-only trail in the existing approved records. A compact table suffices: `time / run identity / unit or phase / decision / reason / evidence pointer / result`. Log meaningful forks, pivots, accepted units, reverts, blocker changes and predicate progress, not every shell command. A new/resumed owner records takeover and the prior range inspected. Supersede incorrect rows with new evidence; do not rewrite failed history into a success story. If exporting tabular data, safely encode tabs/newlines and spreadsheet-formula prefixes from untrusted cells.

At checkpoints derive counts from unit/evidence records and reconcile all dispatched workers, including dropouts and absorbed scope. At close, drain remaining returns, establish terminal ownership for every worker, inspect the real delivered artifact against the predicate, and link current check/review receipts. A required missing slice, unresolved writer or unverified delivery keeps the corresponding completion claim open.

Audit the trail against accessible evidence from this run: resolve pointers, verify claimed actions/results, account for rejected alternatives and failed attempts. Use only authorized current-run transcripts/tool records; do not search unrelated private chats. Missing transcript access limits action-history verification and must be stated, even when file/output evidence is available. Supply the retained trail, relevant current sources, receipts and accessible run evidence to independent Opus under [review](review.md). Review should flag unsupported rows, omitted failures, weak verification and risky scope changes. Fix proven findings with new rows and refresh affected evidence. Retain records for handoff; never delete them to make the program look complete.

## Continue now versus wake later

During an active authorized session, continue toward the agreed predicate, verify each meaningful unit, checkpoint failures and change approach when progress stalls. An autonomous-work request does not authorize unrelated fixes, new external actions, a budget increase or a scheduled service. Out-of-scope discoveries become explicit follow-ups; a settled decision is not repeatedly reopened.

Only when the user asks for later/repeated work, use the host's actual automation tool. Resolve an existing matching automation before creating another. Record requested event/cadence, precise predicate, relevant record paths, scope/authority, stop condition and meaningful notification condition. Verify the tool's returned scheduler state; unavailable scheduling stays unavailable. A watcher process, checkpoint or copied script is not durable scheduling. Never manufacture a scheduled wake, modify global trust/configuration, or treat timeout/default options as consent. Resume from current state and ownership rather than assuming the previous process survived.

Report predicate progress, qualified coverage, gaps/dropouts, remaining workers, blockers and record locations. Optional Benny automations, configurable role setup, style mining, teaching panels and unattended stack-production modes remain separate product choices.
