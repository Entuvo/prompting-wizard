# Day 27 — Failure diagnosis: name the lever, not the model

## Concept

"The model didn't get it" blames a failure without naming a cause, so the fix that follows is usually to rewrite the whole prompt and hope. That works often enough to feel confirmed, and teaches you nothing about which change actually helped.

A real diagnosis names one of the eleven levers or one of the techniques from the last two weeks: the pronoun had no antecedent, the stop condition was never stated, the reasoning steps weren't named. Naming it turns a vague disappointment into a claim you can check — and a claim you can check is a claim you can be wrong about, which is the point.

The fix has to target only what you named. Touch three things at once, and even if the output improves you won't know which one did it. Diagnose on paper first, before you run anything — then run to see whether the diagnosis held.

Here is the test: name the lever before you touch the prompt. If you can't, you're not diagnosing yet — you're rewriting.

## Before / After

**Before**

The tutor asks the learner for a real prompt of theirs that failed — one that produced output they had to discard or heavily rework. If the learner has none ready, the tutor reads `## Log` in `PROGRESS.md`, finds the scored day with the lowest `rubric` score — most recent, if several tie — names that day to the learner, and asks them for the prompt they used that day. If `## Log` has no scored day either, ask the learner for any prompt of theirs that disappointed them; if they cannot supply one, stop and resume the lesson when they can rather than inventing a failure. The log line records the day's topic and its score, not the prompt itself, so the learner supplies it. Either way, the failure is real; nothing here is invented.

**After**

The learner names, in writing, which lever or technique they believe was underspecified — before anyone touches the prompt or runs anything. Where the tier also asks for a fix, the change they'd make goes in the same writing, still before anything runs. Only after that prediction is recorded does the tutor run the original prompt if it hasn't already been run, confirm what actually broke, and check whether the learner's diagnosis, and any fix, targeted the thing that was actually wrong.

## Exercise

Ask the learner for a real failed prompt, or use the lowest-scoring `## Log` entry, per `## Before / After`, before presenting a tier.

### Novice

Have the learner go lever by lever through the failed prompt, out loud, until they find the one they'd bet money was underspecified. Have them name it before anything is run, then run the failed prompt unchanged to confirm what it produces — no fix today.

### Working

Have the learner name the single lever or technique responsible and state the fix for it, then run the original prompt, if not already run, to confirm the diagnosis before applying the fix.

### Advanced

Have the learner diagnose the lever or technique by name and write a fix that changes nothing but the named one — every other lever and technique left exactly as it was — then run both the original and the fixed version and check that nothing else moved.
